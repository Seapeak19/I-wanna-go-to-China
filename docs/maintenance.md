# 资料维护与发布

主站使用人民币核算预算，显示货币独立换算。参考数据与人工查阅事实分开维护，任何脚本成功都不代表完成现场核验。

## 参考汇率与链接

`.github/workflows/maintenance.yml` 计划每日北京时间 06:20 运行，也可在 GitHub Actions 手动运行。GitHub 定时任务可能延迟。任务读取欧洲央行、俄罗斯央行和台湾银行公开数据，保留各自发布日；某来源失败、日期异常或返回挑战页面时保留该来源旧值与旧日期。澳门元按所示港币参考值及联系汇率交叉换算。均非实时成交价。

运行 `node scripts/update-rates.mjs` 可手动维护，审阅 `research/rate-maintenance.json` 与 `currency-core.js` 后提交。台湾银行买卖均值是本站计算值；脚本需识别即期买入/卖出列及原始下载文件的发布时间，无法确认时不更新。

`node scripts/source-health.mjs --limit=40` 每天轮换40条已存来源，记录 HTTP 结果、访问受限和异常。结果在 `research/source-health.json`；成功响应只代表链接可访问，403/429或验证码不代表景点关闭或店铺停业。脚本不会自动改变票价、营业状态、评价或授权状态。

维护任务仅提交汇率和检查快照，再调用 Pages 构建流程发布；不自动修改旅行者本地行程。

## 人工核实

在 `data.json` 逐项保存官方来源、查阅日期、适用票种、范围和有效期。不同场馆分馆、季节票、特展和优惠不能混用。未查明留空并标注待核实，不用网友总花费代替门票。`visitPolicy.closedWeekdays` 为常规闭馆提示依据，节假日和临时安排另核；没有结构化依据时不从泛化文案猜测闭馆日。

票务90天、开放信息30天、美食资料90天进入复核队列。这是编辑维护周期，不是事实有效期保证。`node scripts/quality.mjs` 生成地区缺口统计和复核队列；主站“资料与更新”展示统计，单项仍以详情来源为准。

美食路线中的分餐建议是编辑安排，不能充当营业时间。保留具体分店、菜品、历史人均、评价样本及其原日期；新写路线的编辑日期不冒充近期评价日期。路线新增店铺默认不计费，用户勾选后计入。

## 图片

每张图片保留来源页、原图、作者、拍摄日期、许可及修改说明。只有明确许可或公有领域证据才归入开放许可筛选；原站公开不等于已取得转载许可。更换图片时保存旧来源和下载文件哈希，开放许可署名及相同方式共享要求按原许可执行。历史照片不代表当前现场状态。

## 备份与分享

多个行程保存在浏览器，JSON备份保留手动票价、餐饮开关、住宿交通、个人汇率和每日安排。导入先预览，校验目录身份，创建新行程。分享链接将压缩后的预算与备注放在 URL 片段中；接收者确认导入前不覆盖当前计划。链接可能被接收者或浏览器扩展读取，分享前自行检查备注。无账号与云端同步；清除浏览器数据前应导出备份。

## 构建与独立页面

执行 `npm ci`，安装 `scripts/requirements-images.txt` 中的 Pillow 后，运行 `npm run build`、`npm test`、`npm run check`。Windows 可用环境变量 `PYTHON` 指向 Python 可执行文件。构建生成省份分片、WebP展示图与缩略图、核实统计，以及简体中文/英文省份、城市、景点独立页面、sitemap 和 robots。主站的12种语言保留。

`SITE_URL` 默认为当前 GitHub Pages 地址；迁移托管时设置新的 HTTPS 根地址后重新构建，以更新 canonical、hreflang 和 sitemap。构建清理的仅为项目自身 `dist/`，原始实景照片保留在仓库。发布前检查未知价格仍明确标识、链接与图片来源正确、旧版行程可恢复和手机布局可用。
